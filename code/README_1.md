# Candidate Dossier

Локальное демо на Python + React: собрать документы кандидата, выполнить один запрос для анализа досье и отдельный запрос для оценки по своим критериям.

## Запуск

```powershell
cd C:\work\CUHK\AIE_1903\code
.\setup.ps1
.\start.ps1
```

Откройте http://127.0.0.1:8000. Для уже настроенного окружения достаточно `start.ps1`. После изменения интерфейса выполните `npm.cmd run build` в `frontend` и перезапустите сервер.

## Project 2: вопросы и интервью

- **Questions → Generate questions:** один запрос DeepSeek с актуальными документами, профилем и выбранными критериями создаёт вопросы, пробелы в информации и критерии анализа. Пять факторов показывают полноту документальных свидетельств, а не оценку кандидата. Точные цитаты проверяются по исходным документам. **Needs clarification → Question**, редактирование, добавление, удаление, восстановление и утверждение доступны в интерфейсе. Утверждённые строки выделены светло-зелёным; **Build question overview** и просмотр кандидата содержат только Approved. Изменение вопроса или его критериев возвращает его в Draft. Все изменения сохраняются на сервере. Замена уже созданных вопросов требует отдельного явного запуска.
- **Video Interview Analysis:** загрузите видео или выберите файл из `data`. Копия остаётся в досье. **Transcribe & build Q&A** извлекает аудио через FFmpeg и отправляет трёхминутные фрагменты в `qwen3.8-omni-flash` — до десяти запросов одновременно. Каждый результат сохраняется независимо; ошибка одного фрагмента не отменяет остальные. После полной расшифровки DeepSeek выделяет реально прозвучавшие вопросы и ответы. Текст Q&A собирается из исходных фрагментов, без сочинения ответов или оценки кандидата.
- Слева — видео, справа — **Questions & answers** и **Transcript**. Временные метки перематывают видео. Совпадения с сохранёнными вопросами помечены **Matches Questions**, остальные вопросы — **Additional**. Вступительное выступление может отображаться как **Statement**. Аудио и полный текст можно скачать.
- **Analyze questions:** отдельный явный запрос DeepSeek анализирует только текущие Approved. Поиск идёт по всей сохранённой расшифровке, включая презентацию и ответы на иначе сформулированные вопросы. **Question analysis** показывает исходные фрагменты с тайм-кодами, анализ и покрытие каждого критерия: **Answered / Partial answer / No answer**. Источником служат собственные слова кандидата, а не ответы и обсуждение комиссии; проверенные роли привязаны к хешам исходных файлов. Qwen при этой операции не вызывается.
- Итоговый статус ответа вычисляется сервером по подтверждённым критериям. При явном повторе неудачного анализа сначала проверяется сохранённый ответ: если он проходит проверку и исходные данные не изменились, результат восстанавливается без нового запроса и оплаты.
- **Final score:** под видео отображается покрытие критериев текущего сохранённого анализа. Covered = 1, Partial = 0.5, Not answered = 0; общий балл — сумма баллов всех критериев / их количество × 100 с округлением в конце. У каждого утверждённого вопроса есть балл, исходные ответы с тайм-кодами и **Reasons** с критериями и обоснованиями. Устаревший или отсутствующий анализ не получает числовой балл; новые запросы к модели для этой сводки не нужны.
- Анализ хранится в `interviews/<interview>/question-analysis/`, включая снимок входных данных, исходный ответ, расход токенов и историю запусков. Изменение набора Approved, критериев или расшифровки делает прежний результат неактуальным. Новый запрос запускается кнопкой; повторное открытие использует сохранённый результат. Уже обработанный неизменённый набор берётся из кэша.
- Открытие вкладки, обновление страницы и перезапуск сервера не вызывают модели. Готовые этапы и фрагменты сохраняются; **Resume** продолжает остановленную обработку с недостающего этапа. Автоматических платных повторов нет. Остановка текущего запроса не гарантирует отсутствие списания у провайдера.
- Хранение: `storage/<candidate>/questions/` — вопросы и история запросов; `storage/<candidate>/interviews/<interview>/` — видео, аудио, фрагменты, исходные ответы API, расшифровка и Q&A. В localStorage хранится только выбор открытого интервью. Повторная загрузка того же видео в одно досье использует существующую запись.
- Для видео нужны доступные в PATH `ffmpeg` и `ffprobe`, ключ Qwen и ключ DeepSeek. Ограничения: файл до 2 GB, запись до двух часов с аудиодорожкой. Анализ вопросов оценивает полноту ответов по заданным критериям; итоговая оценка найма и изменение Score не выполняются.

## Досье

1. **New candidate** → имя или номер заявки → **Create dossier**.
2. В **Documents** добавьте PDF/DOCX: CV, teaching statement, research statement, cover letter. Можно выбрать несколько файлов одновременно или добавлять их постепенно.
3. Загрузка только извлекает текст локально. Она **не вызывает LLM**. Одинаковые файлы в одном досье отклоняются.
4. Соберите все нужные документы, проверьте примерную стоимость и нажмите **Analyze dossier**. Все тексты и схема отправляются одним запросом в DeepSeek.
5. В **Profile** доступны Overview, Education, Experience, Publications, Awards, Teaching, Research, Motivation и Links. Ссылки на источники содержат имя документа и исходную страницу или текстовый блок.
6. Результаты сохраняются. Повторный анализ неизменённого успешно обработанного досье блокируется. Добавление/удаление документа делает прежние профиль и оценку неактуальными; новый запрос запускается только вручную.

Нет автоматических повторов даже при неверном JSON, неполном ответе или ошибке сети. После ошибки можно явно запустить ещё один запрос. Тайм-аут не означает, что провайдер не списал деньги.

## Поиск, правки и заметки

- **Tag search** в сайдбаре: выберите теги по интересам, университетам, степеням, должностям или журналам. **Match all tags** ищет пересечение, **Match any tag** — совпадение хотя бы по одному тегу. В поиск входят только актуальные проанализированные профили. Словарь `code/tags.json` задаёт допустимые уровни и статусы образования, а также известные варианты других названий. Он отправляется DeepSeek в том же запросе анализа; сервер проверяет значения. Полное название степени сохраняется отдельно. Для старых профилей короткие теги вычисляются локально без перезаписи исходного ответа и без LLM. Статус без явного подтверждения — Unknown: прошлый год сам по себе не доказывает окончание. Статусы в поиске привязаны к степени, например PhD · Ongoing. Другие категории объединяются только по точным соответствиям из словаря; неизвестные названия сохраняются. После изменения словаря перезапустите сервер.
- **Profile → нужный раздел → Edit section**: исправьте поля, добавьте или удалите записи и выберите источники. В Education уровень и статус выбираются из словаря; изменение полного названия степени сбрасывает оба выбора в Unknown для повторной проверки. **Save changes** обновляет профиль, поиск и JSON-экспорт без LLM. Исходный ответ модели остаётся в `profile.json`, правки — в `profile-edited.json`, журнал до/после — в `profile-edits/`. Оценки продолжают использовать исходные документы. После изменения документов нужны новый анализ и проверка прежних ручных исправлений.
- **Profile → Notes**: личные заметки доступны даже до анализа. Они сохраняются отдельно от сгенерированного профиля, не отправляются в LLM и не влияют на оценку.
- Значок корзины рядом с именем кандидата открывает подтверждение удаления. Удаление окончательно убирает досье, документы, заметки, оценки и историю запросов. Пока запрос анализа или оценки выполняется, удалить кандидата нельзя.

## Шаблоны критериев

Во всех четырёх поставляемых шаблонах есть **GitHub / Open Source — 5 баллов**, общий максимум остаётся **100**. Для Assistant Professor исследовательский план уменьшен с 15 до 10 (4 за вопрос, 3 за метод, 3 за ожидаемый вклад); для USTF service — с 15 до 10; для Dean academic contributions — с 20 до 15; для Academic qualifications publications — с 40 до 35. GitHub оценивается по наличию оригинального публичного проекта с описанной целью (2), конкретных инструкций использования или воспроизведения (2), явной связи с документированными исследованиями или преподаванием (1). Stars, followers и частота активности баллов не дают. Без импортированных доказательств положительная GitHub-оценка отклоняется.

В сайдбаре **Criteria** находится библиотека шаблонов:

- **Assistant Professor**: публикации, образование, преподавание и исследовательский план.
- **USTF**: образование, публикации, преподавание и академическая деятельность.
- **Dean**: руководство, администрирование, образование и академический вклад.
- **Academic qualifications**: исходный общий пример из `code/score.json`.

Все поставляемые шаблоны — редактируемые примеры для демо, а не официальные требования учреждения, включая USTF. Исходные файлы находятся в `code/criteria/` и `code/score.json`. Изменения через интерфейс сохраняются отдельно в `storage/criteria/` и не переписывают исходные файлы проекта.

На странице доступны просмотр разделов и правил, **New template**, **Edit template**, **Import JSON** и экспорт JSON. Формат файла:

```json
{
  "title": "My criteria",
  "sections": [
    {
      "id": "education",
      "title": "Education",
      "max_score": 30,
      "rules": "Award 30 points for an explicitly completed doctorate, 20 for a completed master's, 10 for a completed bachelor's. Use only the highest completed degree."
    }
  ]
}
```

Ограничения: импортируемый файл UTF-8 JSON до 100 KB; 1–20 разделов; уникальные `id` (латиница, цифры, `_`, первая буква); положительные конечные `max_score`; сумма максимумов не больше 1000. Поле `rules` задаёт правила начисления баллов. Можно писать правила по-русски. В редакторе внутренние ID новых разделов создаются автоматически.

В карточке кандидата откройте **Score**, сначала выберите **Criteria template**, затем нажмите **Score candidate**. До выбора шаблона система не разрешает оценивание. Выбор или редактирование шаблона не вызывает LLM.

**Score candidate** делает один отдельный запрос с исходными текстами и выбранными критериями. Сначала показывается примерная стоимость. Полный сгенерированный профиль повторно не отправляется: он дублирует документы и может содержать пропуски. Результат включает баллы, короткие объяснения, недостающие сведения и цитаты. Объяснение раздела ограничено 600 символами, цитата — 800, список пробелов — пятью пунктами по 200 символов. Сервер проверяет разделы, границы баллов и наличие цитат в источниках, а сумму считает сам. Числовой `max_score` задаёт абсолютный предел раздела даже при расхождении с текстом правил.

Оценки сохраняются отдельно для каждой версии досье и критериев. Переключение на ранее использованный неизменённый шаблон показывает сохранённую оценку без нового запроса. Изменение документов или правил делает старую оценку неактуальной; повторный анализ или оценивание запускается только кнопкой.

### История оценок

В карточке кандидата откройте **Score → Score history**. Таблица показывает дату, шаблон, версию досье, общий балл и статус Current/Previous, начиная с новых результатов. Нажмите название шаблона, чтобы открыть баллы по разделам, объяснения, цитаты, недостающие сведения и **Original criteria** — правила на момент оценки. **Export saved assessment** скачивает этот результат в JSON.

История доступна и после изменения документов или критериев, без нового запроса к модели. Для новых оценок сохраняется снимок исходных текстов; старые результаты без снимка показывают сохранённые цитаты, не связывая их с текущими документами. **Request history** отдельно хранит попытки запросов, включая неудачные; **Score history** содержит успешно сохранённые оценки.

Оценка предназначена для проверки человеком. Наличие цитаты не доказывает правильность её интерпретации моделью. Система не принимает решение о найме.

## Сравнение кандидатов

Страница **Comparison** показывает всех кандидатов, выбранные шаблоны и общие баллы. Выбор конкретного шаблона добавляет столбцы его разделов и позволяет сортировать по общей оценке. Таблица использует сохранённые результаты именно этого шаблона, даже если в карточке кандидата сейчас выбран другой.

Неактуальные и отсутствующие оценки отображаются как `—`, а настоящая нулевая оценка — как `0`. Шаблоны с разными правилами не объединяются в общий рейтинг. Клик по кандидату открывает профиль. Просмотр таблицы не вызывает LLM.

## GitHub в разделе Links

1. Загрузите CV: система сама находит GitHub URL в тексте и скрытых гиперссылках PDF/DOCX и импортирует публичные данные без LLM. При запуске сервера уже загруженные документы также проверяются один раз. В **Profile → Links** отображается найденный аккаунт. Если обнаружено несколько аккаунтов, выберите нужный; владельцы репозиториев из ссылок на чужие проекты автоматически кандидату не приписываются. Ручной ввод остаётся только запасным вариантом в сворачиваемом блоке.
2. Импорт запрашивает только публичные данные через GitHub REST API: до 100 последних обновлённых репозиториев и README до шести оригинальных проектов (forks исключаются). README ограничен 3000 символами на проект; ограничения выборки видны в интерфейсе. Код не скачивается и не запускается, внешние ссылки из README не открываются. Это обзор метаданных и README, а не аудит кода или доказательство личного вклада.
3. Снимок сохраняется локально. Обычный повторный импорт того же аккаунта использует снимок. **Refresh** явно получает новые данные; ошибка сети или лимит GitHub сохраняет предыдущий снимок. Ошибка автоматического импорта не отменяет загрузку CV; ссылка остаётся в Links с действием **Retry import**. Нет повторных сетевых запросов при каждом открытии профиля. **Remove** отсоединяет ссылку, сохраняя исходные данные на диске. При удалении CV автоматически связанный аккаунт отсоединяется, если ссылка больше не встречается в оставшихся документах.
4. Импорт не вызывает LLM. **Analyze dossier** отправляет документы и снимок вместе одним запросом. В Links появляется общий анализ с проверяемыми ссылками на источники. Положительные баллы GitHub появляются только после отдельного **Score candidate** с соответствующим шаблоном.
5. Импорт, обновление или удаление снимка изменяет версию досье, поэтому профиль и баллы нужно пересчитать вручную. Ошибки и платные попытки анализа записываются в Request history. GitHub-import не является LLM-запросом.

Если GitHub не импортирован, анализ документов всё равно доступен. Неподтверждённый блок GitHub, который модель может вернуть только по URL из CV, исключается из профиля. Остальные разделы проходят обычную проверку схемы и источников. При наличии снимка анализ GitHub обязан ссылаться на импортированные источники; нарушения отклоняются с указанием причины.

При исчерпании анонимного лимита интерфейс сообщает время сброса, если GitHub его вернул. Для увеличения лимита можно задать серверную переменную **GITHUB_TOKEN** перед запуском или сохранить только токен в `github.txt` в корне проекта (файл исключён из Git). Другой путь задаётся через **GITHUB_TOKEN_FILE**. Переменная **GITHUB_TOKEN** имеет приоритет; файл читается при каждом импорте. Токен не нужен клиенту, не попадает в снимки, LLM или Request history. Приватные репозитории не импортируются. Документация: [репозитории](https://docs.github.com/en/rest/repos/repos#list-repositories-for-a-user), [README](https://docs.github.com/en/rest/repos/contents#get-a-repository-readme), [лимиты](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).

## История запросов

Страница **Request history** в сайдбаре показывает LLM-запросы всех кандидатов: операцию, кандидата, время, Input tokens, Output tokens, расчёт стоимости и статус. Откройте строку, чтобы увидеть **Input** (отправленные сообщения) и **Output** (ответ модели). Новые запросы сохраняют содержимое в локальные `request-<id>-input.json` и `request-<id>-output.json` внутри каталога кандидата. Ключ API и заголовок Authorization в эти файлы не записываются.

История включает неудачные попытки и ручные повторы. Ответ модели сохраняется и при ошибке проверки JSON или цитат. Для старых запросов, сделанных до записи содержимого, input/output могут отсутствовать; приложение не восстанавливает их предположениями. Отсутствующие данные о токенах и стоимости обозначаются `—`.

## Стоимость и модель

По умолчанию используется `deepseek-flash` с отключённым thinking. Название обновлено с `deepseek-chat` по актуальной [документации DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/), проверенной 29.09.2026.

Оценка включает системный промпт, JSON-схему и весь входной текст. Перед кнопкой запуска показана примерная стоимость. Это приблизительное значение, **не жёсткий предел расходов**. Используются пиковые тарифы без скидки: для Flash вход $0.30, кэшированный вход $0.006, выход $1.20 за миллион токенов; вне пиковых часов фактический тариф может быть ниже.

**Request history** сохраняет операции, статусы, реальное использование токенов из ответа API и расчёт стоимости по настроенным тарифам. Если провайдер не вернул usage, стоимость обозначается как неизвестная, а не нулевая. Ошибочный ответ с usage также сохраняет расходы.

Переменные окружения:

- `DEEPSEEK_API_KEY`: API-ключ.
- `DEEPSEEK_KEY_FILE`: путь к локальному файлу ключа. По умолчанию используется существующий `C:\work\DONTDELETE\deepseek_aie1903.txt`.
- `DEEPSEEK_MODEL`: другая модель. Для неизвестной модели цена не выдумывается.
- `DEEPSEEK_INPUT_USD_PER_M`, `DEEPSEEK_CACHED_USD_PER_M`, `DEEPSEEK_OUTPUT_USD_PER_M`: собственные тарифы; задавайте все три вместе.
- `QWEN_API_KEY` (или `DASHSCOPE_API_KEY`): серверный ключ распознавания аудио.
- `QWEN_KEY_FILE`: файл ключа Qwen; по умолчанию `C:\work\DONTDELETE\qwen-voice.txt`.
- `QWEN_BASE_URL` (или `DASHSCOPE_BASE_URL`): совместимый HTTPS API; по умолчанию `https://dashscope.aliyuncs.com/compatible-mode/v1`. Модель распознавания — `qwen3.8-omni-flash`.
- `QWEN_CHUNK_CONCURRENCY`: число одновременных запросов распознавания, от 1 до 10; по умолчанию 10. Значение 1 включает последовательную обработку. Время каждого запроса сохраняется в receipts.
- `CV_STORAGE`: каталог сохранения досье.
- `GITHUB_TOKEN`: GitHub API-токен для серверного импорта.
- `GITHUB_TOKEN_FILE`: путь к файлу токена; по умолчанию `github.txt` в корне репозитория. Файл содержит только токен, без подписи или кавычек.

Ключи читаются только сервером, не передаются браузеру и не включаются в сообщения об ошибках. Платные запросы запускаются только явными действиями анализа, оценки, генерации вопросов или обработки интервью.

## Ограничения и хранение

До 12 документов по 15 MB, до 80 страниц на PDF, до 120 000 символов суммарно. Сканированные PDF требуют предварительного OCR. Старые `.doc` нужно сохранить как `.docx`. Длинные тексты отклоняются целиком, без скрытого обрезания. Предел ответа — 16 000 токенов; неполный ответ не публикуется как готовый профиль.

В DOCX нет стабильной нумерации страниц, поэтому используются текстовые блоки с сохранением порядка абзацев и таблиц. Источники всех файлов имеют уникальные внутренние ID, а интерфейс показывает исходную страницу/блок каждого документа.

Старые сохранённые профили автоматически превращаются в досье с одним документом при запуске. Оригиналы и готовые профили сохраняются. Удаление файла из досье отсоединяет его; исходник остаётся на диске. История платных операций сохраняется при изменении документов и критериев.

Локальное демо без авторизации, привязано к 127.0.0.1. Используйте один процесс Uvicorn: очередь и блокировки находятся в памяти процесса.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
cd frontend
npm.cmd run build
```

Тесты используют искусственные документы и подменённые ответы модели, не тратят API-баланс. Проверяются отсутствие вызовов при загрузке, один запрос на запуск, отсутствие автоматического ремонта JSON, границы баллов, цитаты, обязательный выбор шаблона, восстановление оценок при переключении критериев, история оценок с исходными критериями и снимками, сравнение только актуальных результатов, input/output без ключа API, ручные повторы, сохранение после перезапуска и миграция старых профилей. GitHub-проверки охватывают ссылки из CV и скрытых гиперссылок, импорт и его ограничения, подтверждение источников, обработку неподтверждённого блока, чтение токена и приоритет переменных окружения.
